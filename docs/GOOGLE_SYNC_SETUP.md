# Подключение Google и Firebase с нуля

Облачный проект создаёт владелец приложения в своём Google-аккаунте. Пароль Google, service-account JSON и закрытые ключи в приложение или чат передавать **не нужно**.

Без `app/google-services.json` приложение собирается и работает офлайн. В настройках отображается сообщение, что Firebase ещё не настроен, а кнопка входа недоступна. Это не рабочая облачная конфигурация: реальный вход и обмен между устройствами можно проверить только после следующих шагов.

## 1. Создайте проект

1. Откройте [Firebase Console](https://console.firebase.google.com/) → **Create a project / Создать проект**.
2. Задайте имя, например «Slovarik». Google Analytics можно не включать: приложение его не использует.
3. Для начала можно использовать Spark без подключения платёжной карты, если доступно для вашего аккаунта. У Firestore есть квоты чтения, записи и хранения. Если выбираете платный план, заранее настройте бюджетные уведомления: это не жёсткий лимит расходов.

## 2. Зарегистрируйте Android-приложение

1. В проекте добавьте Android-приложение с package name **`com.slovarik.app`**.
2. Получите отпечатки сертификата на этом компьютере:

   ```powershell
   .\gradlew.bat :app:signingReport --console=plain
   ```

3. Добавьте **SHA-1 и SHA-256 debug-сертификата** в настройки Android-приложения Firebase. Для будущей публикации отдельно добавьте отпечатки сертификата подписи из Google Play App Signing; debug-отпечаток не заменяет release.

## 3. Включите вход Google

1. **Build → Authentication → Get started → Sign-in method → Google → Enable**.
2. Выберите support email, сохраните.
3. При необходимости заполните экран согласия OAuth в связанном Google Cloud-проекте. Если приложение находится в режиме Testing, добавьте используемые Google-аккаунты в test users.
4. Снова скачайте **`google-services.json`** из Project settings после включения Google и добавления отпечатков.
5. Поместите файл в **`app/google-services.json`**, рядом с `app/build.gradle.kts`.

Конфигурация содержит публичные идентификаторы проекта, но исключена из git, чтобы случайно не подключать чужую сборку к вашему облаку. В ней должен присутствовать OAuth web client: плагин создаёт ресурс `default_web_client_id`. Не подставляйте Android client ID вместо web client ID. Не добавляйте service-account credentials в APK.

## 4. Создайте Firestore и закройте доступ

1. **Build → Firestore Database → Create database**.
2. Выберите **Standard edition**, **Native mode**, базу **`(default)`**, подходящий регион и **Production mode**. Не открывайте test mode с доступом всем пользователям.
3. На вкладке **Rules** замените правила содержимым [`../firestore.rules`](../firestore.rules), нажмите **Publish**.

Правила разрешают чтение и запись только в `users/{собственный Firebase UID}/records`. Доступ без входа, к другому UID и к остальным коллекциям запрещён. Окончательные удаления хранятся как отметки: физически удалять их из Firestore вручную нельзя, иначе старое офлайн-устройство может восстановить удалённую запись.

Альтернатива публикации правил через локальный CLI после авторизации:

```powershell
cd firebase-tests
npm ci
npx firebase login
npx firebase deploy --only firestore:rules --project ВАШ_PROJECT_ID --config ../firebase.json
```

Команда deploy меняет реальный проект. Выполняйте её только с вашим явным project ID и после проверки правил; агент автоматически облако не создаёт и правила не публикует.

## 5. Соберите и проверьте

```powershell
.\gradlew.bat :app:assembleDebug :app:assembleDebugAndroidTest
.\start-android.ps1 -NoBuild
```

Для Google-входа нужен телефон или эмулятор с Google Play services и доступом к сервисам Google. Откройте **⋮ → Настройки → Аккаунт и синхронизация → Войти через Google**, прочитайте согласие и выберите аккаунт.

Перед первым входом сохраните локальную JSON-копию. Проверьте сначала на двух **тестовых** установках, а не на единственных копиях важных слов:

- Войти одним аккаунтом, создать папку/колоду/слово на A, синхронизировать, увидеть на B.
- Выключить сеть на A, изменить слово и оценить карточку; включить сеть и проверить слово, прогресс и историю на B.
- Одновременно изменить текст на A и прогресс на B: оба изменения должны сохраниться.
- Отправить карточку в корзину на A, восстановить на B, затем проверить окончательное удаление и повторный вход старого офлайн-устройства.
- Выйти: локальные слова остаются. Войти тем же аккаунтом — очередь изменений отправляется. Другой аккаунт не должен получить эти данные.
- Отменить последнюю оценку: соответствующая запись истории исчезает на втором устройстве после синхронизации.
- Изменить язык, случайное направление и время/состояние напоминаний на A: настройки появляются на B, а разрешение уведомлений на B остаётся под контролем Android.
- Завершить Match с лучшим временем на B, затем синхронизировать старое худшее время с A: на обоих устройствах остаётся лучший рекорд. Восстановленная из корзины колода сохраняет рекорд.
- После оценки на A синхронизировать B и отменить эту последнюю оценку на B: ровно её событие удаляется, предыдущее расписание возвращается на обоих устройствах. Несовместимая с более новым ответом отмена не применяется.

Автоматический обмен происходит в открытом приложении примерно раз в 45 секунд вне занятия, после локальных изменений и через WorkManager при доступной сети (периодическая задача — от 15 минут). Android может откладывать фоновые задачи. Есть кнопка ручной синхронизации. Во время обучения входящее объединение откладывается, чтобы не менять карточку посреди ответа.

## Модель и ограничения первого варианта

- База SQLite обновляется до версии 4 без сброса существующих ID, карточек, расписания и истории. Версия 3 добавляет журнал синхронизации, версия 4 — настройки, рекорды и последнюю отмену. Старые явно заданные SharedPreferences импортируются один раз, включая рекорды колод в корзине. Новая установка не публикует незаданные настройки по умолчанию поверх облака.
- Одинаковые числовые ID на разных устройствах не считаются одной карточкой: используются стабильные идентификаторы. Независимые демонстрационные колоды и одинаковые слова автоматически не склеиваются.
- Содержимое и расписание карточки синхронизируются раздельно. Конфликт одного и того же состояния разрешается по версии и идентификатору устройства; одновременные оценки SM-2 не проигрываются заново как единая последовательность. История разных оценок объединяется. Неверные часы устройства могут влиять на выбор победителя.
- Восстановление JSON, заменяющее всю базу, запрещено после связывания. Экспорт JSON доступен. Выход не снимает привязку и не удаляет облачные данные. Безопасного переключения владельца существующей базы пока нет — не пытайтесь обходить защиту редактированием настроек.
- Синхронизируются все сохранённые данные профиля: словарь, корзина, расписание, история, последняя совместимая отмена, рекорды Match, языки, случайное направление и предпочтения напоминаний. Настройки объединяются по ключам; Match сохраняет минимум времени. Разрешения Android, установленные голоса, токены входа, незавершённые раунды и временный ввод на экране не переносятся. Восстановление Android backup/клонирование одной установки между устройствами пока не поддержано как способ миграции синхронизированной базы; используйте вход на чистой установке.
- Передаются тексты словаря, корзина, расписание и история. Firebase защищает транспорт и хранение, но это **не сквозное шифрование**. Встроенный перевод по-прежнему работает на устройстве и сам по себе не отправляет запросов.
- Первая версия загружает полный список записей аккаунта при каждом цикле. Для больших словарей нужно учитывать расход квот; инкрементальная загрузка и отдельный интерфейс разрешения конфликтов остаются дальнейшими улучшениями.
- После обновления до полного профиля **снова опубликуйте текущий `firestore.rules`**: прежние правила не разрешают новые типы записей `settings`, `match` и `undo`. Обновите приложение на всех синхронизируемых устройствах установкой поверх старой версии, без удаления данных. Старые сборки не понимают расширенный протокол и требуют обновления.
- Перед публичным выпуском нужны проверка реального входа/двух устройств, политика конфиденциальности и сценарий удаления аккаунта и облачных данных. Одного выхода из аккаунта для удаления недостаточно.

## Локальные проверки без реального Firebase-проекта

```powershell
cd firebase-tests
npm ci
npm test
```

Тесты запускают локальный Firestore Emulator с project ID `demo-slovarik-sync`; без переменной эмулятора сами тесты отказываются работать. Нужны Node.js 20+ и JDK 21 в PATH. Это проверяет правила доступа, а не настоящий Google OAuth.

Официальные инструкции: [Firebase Android setup](https://firebase.google.com/docs/android/setup), [Google sign-in с Credential Manager](https://firebase.google.com/docs/auth/android/google-signin), [Firestore Security Rules](https://firebase.google.com/docs/firestore/security/get-started).
