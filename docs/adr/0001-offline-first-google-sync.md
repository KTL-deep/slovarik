# Необязательная синхронизация через Google и Firebase

Пользователь выбрал объединение данных между устройствами, а не хранение резервных копий в Google Drive. SQLite остаётся основой офлайн-обучения; Google Credential Manager и Firebase Authentication устанавливают личность, а Firestore хранит изменения только в пространстве соответствующего Firebase UID.

Локальные числовые идентификаторы не переносятся между устройствами: синхронизация использует стабильные идентификаторы, версии и сохраняемые отметки окончательного удаления. Содержимое карточки и прогресс повторения объединяются отдельно; одновременно изменённая одна и та же сущность разрешается детерминированно по версии и идентификатору устройства. Это не повторное проигрывание нескольких независимых оценок SM-2: история объединяется, но у карточки остаётся одно победившее состояние расписания.

Первое связывание требует явного согласия на передачу локального словаря, корзины и истории. База остаётся связанной с одним UID даже после выхода: другой аккаунт не должен незаметно получить эти данные. Восстановление заменяющей JSON-копии в связанной базе запрещено до появления отдельного безопасного сценария облачной замены. Настройки интерфейса, напоминания, локальная отмена и рекорды Match пока не синхронизируются.

Без конфигурации владельца проекта приложение собирается и работает офлайн; UI явно сообщает, что облако ещё не настроено. Firebase-проект и его правила должны быть настроены и проверены до использования облака с реальными данными. Аналитика и рекламные SDK не добавляются.
